Person Server

Your Person Server

In AAuth, your Person Server (PS) is the party that speaks for you. Agents ask it before they act for you. Resources trust what it signs.

What this PS does in the demo

  1. Identifies you to a resource. When an agent needs to act for you at a resource, the PS has you sign in and issues a person token with a pseudonymous ID that's unique to that resource. This grants no permissions. If you're already signed in, it happens without a click.
  2. Asks for your consent. When the resource wants proof of permission, the agent brings a resource token here. The PS shows you exactly what's being requested and, if you allow it, issues an auth token bound to that agent's key. Tick "Always allow" and future requests for the same thing are approved without asking, until you revoke them.

Sign-in is a display name only. This is a demo, not a real identity provider.
